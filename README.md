# Archive

A clean, minimal, public file archive. Folders, search, sorting, list and grid views, and in-browser previews. No backend, no build tools, no dependencies.

## How it works

`index.html` reads a `files.json` manifest and draws the archive from it. `build.py` generates that manifest by scanning the `files/` folder, so you never index anything by hand.

```
.
├── index.html
├── build.py
├── files.json        generated by build.py
└── files/            put your files here
    ├── beats/
    └── tapes/
```

Subfolders inside `files/` show up as folders in the archive.

## Adding files

1. Drop files into `files/` (subfolders are fine).
2. Run:
   ```
   python build.py
   ```
3. Commit and push, including the updated `files.json`.

Files whose names start with a dot (like `.DS_Store`) are skipped.

## Hosting on GitHub Pages

1. Push this repo to GitHub.
2. Go to **Settings > Pages**.
3. Under **Build and deployment**, set **Source** to **Deploy from a branch**.
4. Pick your main branch and the `/ (root)` folder, then save.
5. Your archive will be live at `https://<username>.github.io/<repo>/` after a minute or two.

The page has to be served over http. Opening `index.html` straight from your disk will not load the file list.

## Supported previews

| Type | Extensions |
| --- | --- |
| Images | jpg, jpeg, png, gif, webp, svg, avif |
| Audio | mp3, wav, flac, ogg, m4a, aac |
| Video | mp4, webm, mov, mkv |
| Documents | pdf (viewer), txt, md (plain text) |

Every other file type is still listed. Clicking it downloads it. `mov` and `mkv` often won't play in browsers, so use `mp4` or `webm` when you can.

To change the badge colors or add extensions, edit the `EXT` object near the top of the script in `index.html`.

## Limits

- GitHub recommends keeping a repo under about 1 GB, and blocks single files over 100 MB.
- Everything in `files/` is public and reachable by direct link, even if you never open the page. Don't put anything in there you wouldn't want out.
- For large audio or video, host the files in a bucket (Cloudflare R2, S3, etc.) and change the `url()` function in `index.html` to point at it.

## Optional: auto-build on push

If you'd rather just upload files and let GitHub rebuild the manifest, add this as `.github/workflows/index.yml`:

```yaml
name: Build index
on:
  push:
    paths: ["files/**"]
permissions:
  contents: write
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: python build.py
      - run: |
          git config user.name "github-actions"
          git config user.email "actions@github.com"
          git add files.json
          git diff --staged --quiet || git commit -m "Update files.json"
          git push
```

Note that file dates come from the checkout time on GitHub's runner, so "Newest" and "Oldest" sorting won't reflect your original file dates when built this way. Run `build.py` locally if the dates matter to you.
